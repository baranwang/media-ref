# 0005 证据门的分集级信号：标题对位、片长和年份推翻

状态：草案（2026-11-28）

## 2026-11-28 修订：集数是映射的参数，不是身份

起因是变更单 9c286cc0：腾讯「古乐风华录」（`mzc002001plkc0p`）首播前一天被提交，类型、年份、片名都对上，段是第 1 季第 1 集起、不写结尾。合集在线但还没有分集，TMDB 第 1 季 40 集都排在之后播出。证据门判 `needs_review`，审核 agent 驳回。驳回不是模型拿不准：就算它放行，`positionMisfit` 也会把不写结尾的段解析成「到第 0 集」而挡下；探索 agent 的 `checkSegmentsFitCollection` 遇到 0 集合集也一律拒交。集数在这里成了能否通过的硬门槛。本节改成：**身份（类型、年份、片名、共同编号）决定能不能通过，集数只决定映射现在覆盖到第几集。** 以本节为准，下文和其他 ADR 冲突时按本节执行：

- **有段的剧集，第一步不再核对集数**（`fieldChecks.episodeCount` 记 `skipped`）。集数改由第二步按段核对：写了结尾的段照旧要和条数严格一致，不写结尾的段只要落在范围内。电影和没有段的整部关联不变。
- **0 和未知分开。** 合集在线、列表里只有预告片时报 0（腾讯 adapter 先改，其他 adapter 仍报 `null`）；列表整个为空或读不出来、分章节、集号断档等数不清的情况仍报 `null`。第二步只把 `null` 当缺失（`segment_episode_count_missing`），`null` 照旧不能自动通过。
- **未开播的季。** `lastAiredEpisode` 在第一集排在今天或之后时返回 0（第一集没有日期仍算不知道，避免 e4c9fdd 修过的「完结季缺日期被当成在播」重新出现）。合集为 0 集（或要和已有关联比较）时，取证任务用它在 `evidence.catalog.unairedSeasons` 里记下未开播的季；第二步对这些季最后一个不写结尾的段把最少条数从 1 降到 0。所以上面这张单会直接通过，存成不写结尾，开播后新出的集自动算进来。已开播的季遇到 0 集合集仍是 `segment_episode_count_mismatch`，交给审核 agent。
- **探索和审核的代码复核同步放宽，但只放宽空位。** 未开播季不写结尾的段，只有在合集从它的起始位置起还没有任何正片时才不要求落在合集里，它的起始位置仍参与重叠检查；合集在那个位置已经有正片（多半是别的季），探索直接拒交，审核按原规则核对（首播当天 TMDB 还显示未播、平台已上第 1 集的情况照旧能过）。写了结尾的段仍要落在已拉到的正片里。`get_catalog_season` 对未开播的季报 `stillAiring.lastAiredEpisode: 0`，两个 agent 的提示词都写明这时空合集就是这一季。
- **仍然挡下的**：合集比整季长（多半混了先导片或花絮，位置可能错开，审核 agent 对位）；写了结尾却超出合集；越界、重叠、类型不对、共同编号冲突。

代价：[ADR 0002](0002-exploration-agent-redesign.md) 把集数核对当作先导片错位的兜底，现在条数不超过整季时错位看不出来，即上文的漏洞 2，留给第 1 节的标题对位去补。失效复查除了第一步，还会重跑第二步里按段核对条数的部分（`featureEpisodeCount` 的冲突），平台把合集删短、段声称的位置不在了，照样报 `association_content_mismatch`；第二步的其他检查仍不在复查里跑。未开播时通过的关联，开播后不会自动复核平台第 1 位是不是正片；要补，得按 [ADR 0004](0004-no-waiting-states.md) 的模式加一个有额度的首播后复查任务。

## 背景

另一个会话调研了 huangxd-/danmu_api 的合并逻辑（`danmu_api/utils/merge-util.js`，AGPL-3.0，只借思路，不复制代码），提出五个候选信号。本文判断它们能否让证据门（`packages/core/src/evidence-gate.ts`、`season-coverage.ts`）和审核 agent 的代码复核（`review-agent.ts`）少放错、少驳错。依据[宪法](../../CONSTITUTION.md)，信号只能让系统更保守，或在证据更强时放行，不能产生需要人处理的状态。

### 现在怎么判

第一步核对身份。双方都取到了同一个外部编号，就直接通过；编号冲突则判 `shared_id_conflict`。没有共同编号时，类型、年份、片名都要对上；电影和没有段的关联还要对上集数（有段的剧集见上面的修订）。年份必须严格属于目录的候选年份：首播年、各季首播年，或段起始集的播出年。片名做简繁折叠、去符号，并剥掉「第N季」、括号和与年份相同的结尾。集数必须等于某几季连续相加的和。

第二步核对段：季存在，段起始集的播出年与合集年份严格相等，集号不越界，线性段的平台位置从 1 起连续，总条数与段的集数一致。季覆盖（`seasonCoverageConflict`）只检查非线性段和只覆盖一季开头的线性段，用分集副标题和「第N期上/下」核实是否播到了大结局，或者有没有超出前缀。

两步任何一项对不上都会标成 `needs_review`，由审核 agent 判定（[ADR 0003](0003-review-agent.md)）。`shared_id_conflict`、`media_type_mismatch`、`segment_episode_out_of_range` 和 `segment_season_not_found` 不能推翻。片名、年份和集数冲突只要模型逐条写了理由，代码就会放行，不另外要求证据。

### 现在的准确度

#78 的评测有 38 个样本，取自生产环境的真实关联。末轮 38 个全部判对，误放行和误驳回都是 0。线上真实出过的两例季号错误（灵笼第二季提交成第 1 季、妻子的浪漫旅行第 8 季提交成第 6 季）都被驳回。评测里人造的错误主要靠片名、年份、起始位置或总条数这些结构规则拦下。所以这里要补的不是已经观察到的回归，而是代码里能证实的结构漏洞，以及模型推翻冲突时缺少的代码复核：

1. **整季线性段从不核对分集内容。** `seasonCoverageScopes` 只覆盖非线性段和前缀段；整季段写了结尾，或者没写结尾（还在播），都不经过季覆盖。同一年、集数相同的另一季，或同名、同年、同集数的另一部作品，可以只凭年份和集数通过（`exploration-agent.ts` 的 `passesGate` 注释也指出第一步有这个问题，第二步只多核对了段的年份）。
2. **条数没变时，位置可能已经错开。** 连载中的季使用不写结尾的段，条数只要落在 `[1..整季]` 就能通过。平台列表混入一条没被过滤的花絮后，后面的位置整体错开一位，条数检查看不出来。
3. **电影的第二步整体跳过。** 电影只核对片名、年份、类型和「1 集」。同名同年的另一部片，或者变体说明里没写出来的精编、解说版，都拦不住。
4. **模型推翻年份冲突时只要一句理由。** 降世神通（B 站 2023 年上架，原作 2006 年）和霸王别姬（B 站标 2013 年）在评测里放行是对的，但代码只检查理由写了没有，不检查有没有分集层面的证据。

## 拟议决定

| 信号                         | 能修的错                          | 引入的风险                                | 结论                             |
| ---------------------------- | --------------------------------- | ----------------------------------------- | -------------------------------- |
| 分集标题对位比对（原 2）     | 漏洞 1、2：错季、错位、同名异作   | 译名差异导致误判不符，审核 agent 负担增加 | **采纳**，先影子运行，第一个做   |
| 推翻年份时要分集证据（原 4） | 漏洞 4：模型放行缺证据            | 缺片长时会误挡对的电影                    | **采纳**，改造后用于审核复核     |
| 片长（原 1）                 | 漏洞 3（电影）；为 4 提供电影证据 | 平台删减、片头片尾、数据缺失              | **部分采纳**：电影；剧集只作诊断 |
| 同列表续作（原 3）           | 证据门里不存在这类错              | 不适用                                    | 不采纳                           |
| 多平台集数众数切季（原 5）   | 目录已有每季集数，没有要修的错    | 把未核实的合集当权威，平台间错误相关      | 不采纳                           |

所有新信号都遵守下面四条：

- **缺数据就弃权。** 取不到、样本不够或语种不一致时不产生任何结论，判定和现在完全一样。弃权既不拦单，也不放行。
- **只有两种作用。** 一是加一个新冲突码，把单子交给审核 agent（可以推翻，模型能看到比对的样本）；二是在 `approvalBlocker` 和 `correctionBlocker` 里多加一项代码复核。本轮不让任何信号单独把原本不通过的单子变成通过。
- **放在第二步。** 失效复查只重跑第一步（`invalidation.ts`），新规则不会在没有新证据时把已确认的关联降级。种子取证（`seeds.ts`）、探索的 `passesGate`、`conflict-resolution.ts` 的新旧比较都调用同一个 `evaluateEvidenceGate`，会一起生效，新旧两边按同一套规则比。
- **结论可追溯。** 每次计算的样本对、相似度、片长和阈值都写进 `evidence.gate.signals`，弃权也记下原因。

### 1. 分集标题对位比对（采纳）

danmu_api 的 `probeContentMatch` 先从两份列表里各自均匀抽标题，再两两比较，因为它不知道两边的集是怎么对应的。这里的段已经写明了「平台位置 p 对目录第 e 集」，所以改为**按段对位抽样**：在每个线性段的覆盖范围内均匀取至多 5 个位置，第一集和最后一集必取，比较平台位置 p 的标题和目录第 e 集的标题。

- **规范化**沿用 `season-coverage.ts` 的 `subtitle()`：去掉「第N集」前缀和剧名，转小写，去符号，再去掉数字和综艺花絮标记，少于 4 个字的不用。TMDB zh-CN 缺译名时返回的「第 N 集」会因此被丢掉。双方都有可用副标题的才算一对。
- **相似度**用简繁折叠（`foldCjkVariants`）后的字符二元组 Dice 系数。少于 3 对，或者一边是中日文、另一边是拉丁字母时，弃权。
- **不符**：至少 80% 的对相似度低于 0.3，就记第二步冲突 `episode_titles_mismatch`。如果把平台位置前后错一位后有至少 60% 的对相似度超过 0.6，冲突说明里写「疑似错开一位」，方便审核 agent 改正。
- **相符**：至少 60% 的对相似度超过 0.6，只记为 `matched`，本轮不改变判定，留给第 2 节和以后使用。
- **数据**：`fetchSegmentEpisodeEvidence` 现在只拉季覆盖和中途起始的季。改为也拉每个有线性段的季，每季一次 TMDB 请求，同一任务内复用。取不到时弃权，不抛错，这样故障不会被当成反证。

**能修的错**：同年同集数的错季、同名同年同集数的另一部作品，以及条数没变但位置错开（漏洞 1、2）。**风险**：TMDB 的志愿者译名和平台官方标题可能差别很大，导致对的单子判成不符。代价是多一次审核会话（当天额度 200）；模型如果解释不了，单子会被驳回，需求按退避稍后重试。这只会暂时少一条关联，不会写错数据。阈值必须先经影子运行校准（见实施顺序）。

### 2. 审核 agent 推翻年份冲突时要有分集证据（采纳，改造）

danmu_api 的 `checkDateMatch` 允许年份相差 1 年，相差更多时才要求分集证据。证据门现在要求年份严格相等，比它更严，**不放宽**。这条思路改用在审核 agent 的推翻上：模型放行（或改正时沿用原提交的）`year_mismatch` 或 `segment_year_mismatch`，而年份相差超过 1 年时，代码还要求至少一条正面的分集证据，否则按 `year_override_unsupported` 驳回：

- 剧集：第一步的集数匹配或第二步的段条数通过，并且第 1 节的结论不是不符；或者第 1 节判为相符。
- 电影：第 3 节的片长相符。电影的「1 集」对上不算证据。片长弃权时也挡下。

按评测核对：降世神通第二季两边都是 20 集，可以通过；霸王别姬依赖第 3 节，所以本节必须在第 3 节之后上线。相差 1 年以内维持现状（跨年首播、上架时间差）。

**能修的错**：模型用说得通的理由放行了年份差很大的错作品，即漏洞 4。评测里还没出现过，这是一道针对模型输出波动的保险。**风险**：平台缺片长的老电影，原本模型会正确放行，现在会被驳回，需求稍后重试。

### 3. 片长（部分采纳）

TMDB 网关目前丢弃了片长。电影详情接口有 `runtime`，季接口的每集也有 `runtime`。各 adapter 已经采集 `FeatureEpisode.durationSeconds`，但只在 `exploration-tools.ts` 展示给 agent。

- **3a 电影，采纳。** `CatalogEvidence` 增加电影片长。平台取唯一一条正片的时长；有多条时取最长的一条，并记下条数。两边相差超过 15 分钟且超过 15% 时，记第二步冲突 `movie_runtime_mismatch`（可推翻）；两边都在容差内为相符，任一边缺失就弃权。15 分钟用来容纳大陆删减版和片头片尾差异，精编版、解说版和另一部片通常会超出。容差同样要经影子运行校准。
- **3b 剧集，只作诊断。** 不用片长判断类型：`media_type_mismatch` 不能推翻，用片长去推翻它就是放宽规则。B 站番剧频道的电影（#141）已经在 adapter 里读显示类型修掉了，根因应该在 adapter 修。平台单条中位时长约为目录单集一半、条数约为两倍时（上下拆分），只在集数冲突的说明里注明，帮审核 agent 选择非线性段，不改变判定。线性段范围内时长不到中位数 30% 的条目（漏掉的花絮）先只在影子里记录：泡面番、总集篇和双倍长度的首集都会造成误判，要看到真实命中再决定要不要升级成冲突。

### 4. 同一搜索结果里的续作（不采纳）

`detectPeerContextSequels` 是给模糊合并用的：同一批搜索结果里同时有「X」和「X R」时，把后者当续作，防止它被并进 X。证据门每次只看提交的那一个合集，没有同批结果。规范化后的片名比较是精确匹配，「X R」对「X」本来就判 `title_mismatch`，反过来也一样，不存在这类误放。探索 agent 看搜索结果时已经能看到整份列表，由模型判断。

一个相近的想法是：合集标题里写的季号和提交的季号不一致时记冲突。它也不采纳，因为平台季号经常和 TMDB 不同，例如咒术回战第二季对应 TMDB 第 1 季第 25–47 集，斗破苍穹年番对应第 5 季，会把大量对的单子推给审核 agent。第 1 节能更直接地发现同年错季。

### 5. 多平台集数众数切季（不采纳）

`buildSeasonLengthMap` 在没有权威分季时，用多个来源的集数众数推断每季长度。这里段的基准是 TMDB 的每季集数（[ADR 0001](0001-unified-association-model.md)），已经有权威分季。TMDB 把几季并成一季时（咒术回战 59 集），用段的集号范围和逐集播出年解决。拿平台集数投票，等于把还没核实的合集当成权威。各平台的元数据常常来自同一上游，错误会相互关联。如果用已有关联投票，又会自己证明自己；平票时取较小值也没有依据。

## 实施顺序

1. **影子运行。** 在 `evidence-job.ts` 和 `seeds.ts` 里计算第 1 节和第 3 节的信号，写入 `evidence.gate.signals`，不影响判定。用 #78 的 38 个样本和生产环境所有已确认的平台关联离线回放，统计每个阈值下的误判不符率和弃权率。
2. **启用第 1 节。** 条件是已确认关联中被判为不符的为 0，或者每一例都能找到确实错了的证据。阈值按回放结果定稿。
3. **启用 3a**：TMDB 网关取电影片长，启用 `movie_runtime_mismatch`，启用条件同上。
4. **启用第 2 节**，它依赖第 1 节和 3a。
5. 3b 保持诊断用途，看过影子数据再另行决定。

每一步上线前都重跑审核 agent 评测，38 个样本要保持全对，并补上能复现漏洞 1–3 的单元测试样本。

## 后果

- 更多单子会交给审核 agent，耗费 token 和当天额度；第 1 节每季多一次 TMDB 请求。
- 少数对的单子会因译名差异或片长缺失被驳回，需求按退避稍后重试。按宪法，这是「拿不准就不写入」可以接受的代价。
- 本轮没有任何信号能让原本不通过的单子自动通过，审核 agent 的负担只增不减。等影子数据证明「标题相符」足够可靠后，再考虑让它替代模型处理部分年份或片名冲突。

## 未决问题

- 相似度的阈值（0.3、0.6、80%、60%）是照搬 danmu_api 的，TMDB zh-CN 译名和平台标题的实际分布还没测。短标题用二元组 Dice 是否合适，也要看回放结果。
- TMDB zh-CN 对国产剧和国创动画分集标题的覆盖率有多高？如果大多弃权，第 1 节只对动画有效。
- 各 adapter 的 `durationSeconds` 有多可靠：腾讯的 `duration`、芒果的 `time`、爱奇艺两个入口的格式是否一致？有没有只返回预告片时长的情况？
- 电影片长容差取 15 分钟和 15% 是否合适，加长版和导演剪辑版是否应该按变体处理而不是判冲突？
